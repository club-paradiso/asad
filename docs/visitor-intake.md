# 제주출입국 방문 목적 사전접수 · ASAD 실시간 연결

> 시범 기능. 공식 출입국 시스템이 아니며, 기관 보안·운영 승인 전 실제 민원에 사용하지 마세요.

## 주소

- **iPad 민원인용**: ASAD 배포 주소의 \`/intake\`
- **직원 데스크톱**: 같은 ASAD 배포 주소의 \`/secret\` (주 모니터에서 접수 내역 관리, 보조 모니터에서 민원인용 화면 실행)
- GitHub Pages의 \`apps/visitor-intake/\`는 **정적 데모**이며 실시간 전송을 수행하지 않습니다.

## 사용

1. 직원 컴퓨터의 **주 모니터**에서 \`/secret\` 접속 → 창구 번호를 **반드시** 고른 뒤 **시작** 클릭. 창구 번호는 서버의 창구 세션에 저장되고, 이 창구로 들어온 모든 요청에 같은 번호가 찍힙니다.
2. **듀얼 모니터 운영**: `보조 모니터에 민원인 화면 열기` 클릭 → 새 탭이라면 독립 창으로 분리 → 보조 모니터로 이동 → 해당 화면의 `전체화면` 버튼 또는 데스크톱 브라우저의 F11 사용. 직원 확인 화면은 주 모니터에 유지합니다.
   - 모니터 자동 배치는 운영체제·브라우저 권한에 따라 제한됩니다. Windows에서는 별도 창을 선택하고 `Win+Shift+←/→`로 다른 모니터로 옮길 수 있습니다.
   - 기존 **iPad/모바일 운영**: 화면의 10자리 접수 코드 또는 QR을 이용해 같은 ASAD의 `/intake?desk=코드` 열기. 보조 모니터 없이도 가능합니다.
   - 새 창에 관리자 인증 토큰은 포함되지 않습니다. 새 창 링크에는 공개용 창구 코드와 표시용 창구 번호만 들어갑니다.
3. 민원인이 언어(15종, 필리핀어·싱할라어·크메르어·미얀마어 추가) → 업무(20종) → HiKorea 예약 자기신고(3종) 선택 → **직원에게 확인 요청하기**(선택한 언어로 표시).
   - `예약함`을 고르면 터치 숫자 패드로 **예약 번호 1~108번**을 입력할 수 있습니다. 오늘 예약은 번호를 몰라도 제출 가능하지만, **다른 날짜로 예약함**을 고르면 날짜(연월일 8자리, `YYYYMMDD`)와 1~108번 사이의 예약 번호를 둘 다 입력해야 합니다. 존재하지 않는 날짜·0·109 이상의 번호는 거절됩니다. 날짜와 예약 번호는 민원인의 자기신고로서 공식 HiKorea 예약 조회 결과가 아닙니다.
   - 언어를 고른 뒤에는 버튼·안내·오류 문구가 모두 그 언어로 바뀝니다(`data.json`의 `kiosk` 항목). 전송 실패 시 민원인 언어 안내 아래에 직원 확인용 한국어 원인을 함께 표시합니다.
   - 전송 완료 화면은 30초 뒤 언어 선택 화면으로 자동으로 돌아갑니다. 업무·예약 선택 화면에서 2분 동안 조작이 없으면 이전 민원인의 선택을 지우고 처음으로 돌아갑니다.
   - **전체화면 진입 후에도 전환/종료 버튼은 남습니다.** 보조 모니터의 민원인 화면에서 직접 눌러 진입하고, 종료는 같은 버튼 또는 Esc 키를 사용합니다. 창을 열기만 하면 자동 전체화면이 되지는 않습니다.
   - 일반 iPad 방문객 URL에서도 전체화면 버튼을 표시합니다. iPad Safari에서는 브라우저 전체화면 API 제한이 있을 수 있으므로, 사이트를 Safari의 **공유 → 홈 화면에 추가**로 설치한 다음 홈 화면 아이콘으로 실행해야 브라우저 주소창을 숨길 수 있습니다. 기기에 따라 상태 표시줄은 남으며 실기기 테스트가 필요합니다.
   - 단일 오프라인 HTML(`file://`)의 민원인 보조 창에도 독립적인 전체화면 버튼을 넣었습니다. 로컬 HTML은 iPad 홈 화면 웹앱으로 실행할 수 없으며, 브라우저가 허용하지 않으면 Windows F11 또는 해당 기기의 제한 안내를 표시합니다.
4. 직원 화면은 민원인 화면을 **그대로 비춥니다**. 민원인이 언어·업무·예약 여부를 누를 때마다 `/api/intake/live`로 현재 화면 상태(언어 코드, 업무 번호, 예약 응답, 예약번호·예약 날짜 선택, 단계)를 보내고, 직원 화면은 이를 큰 카드로 보여 줍니다. 직원이 누를 버튼은 없습니다.
   - 갱신 주기: 최근 60초 안에 변화가 있으면 1초, 조용하면 2.5초. 로컬 측정(개발 서버, 메모리 저장소)에서 민원인 탭 → 직원 화면 반영까지 약 0.8초. 실제 배포(Upstash Redis)에서는 측정하지 않았습니다.
5. 민원인이 보낸 요청은 아래 **받은 요청** 목록에 최신순으로 쌓입니다. 표시되는 #번호는 요청 순번이며 번호표가 아닙니다.
6. 예약 증빙 확인과 번호표 발급은 지금처럼 창구에서 직접 합니다. 이 화면은 기록이나 확인 버튼을 요구하지 않습니다. (서버의 기존 확인·발권 기록 API는 남아 있지만 화면에서는 쓰지 않습니다.)
7. **응대 후 직원 안내**: 직원 화면의 **응대 후 · 다음 단계 안내**에서 필요한 항목(통합신청서 작성 / 연장 수수료 수입인지 구매 / ATM 등록증 발급 비용 납부 / 사진 부착)을 체크합니다. **연장 수수료 수입인지 구매** 항목을 선택하면 직원이 금액을 **만 원 단위 정수(1~999)**로 직접 입력해야 합니다. **선택 항목 민원인에게 보여주기**를 누르면 직원이 선택한 항목만 민원인 화면에 해당 언어와 한국어로 번호를 매겨 표시합니다. 수수료와 실제 처리 대상은 자동 계산·검증하지 않으며 직원의 확인된 안내에 따릅니다. 보내기 전에 항목과 금액을 다시 확인하세요.
   - 목록 안내는 30초 자동 숨김을 사용하지 않고, 민원인이 확인을 누르거나 직원이 **화면에서 지우기**를 누를 때까지 유지됩니다. 새 안내를 보내면 이전 안내를 교체합니다. 서버에는 항목 ID와 선택한 수수료 금액만 임시 저장하며 자유입력 개인정보는 저장하지 않습니다.
   - 방문 목적 사전접수 및 고정 안내 문구를 포함한 15개 언어 번역은 **초안**이며, 원어민·실무 검수를 거쳐 운영해야 합니다.
8. 사용 종료 시 **연결 · 창구 닫기 → 창구 닫기**를 클릭. 미종료 세션은 2시간 후 만료.

## 직원별 창구와 모니터 운영

- 서로 다른 직원 PC(또는 독립된 직원 관리 탭)에서 각각 `/secret`으로 새 세션을 시작하면, 서버가 **서로 다른 창구 코드와 직원 토큰**을 발급합니다. 각 창구 대기열은 직원 토큰으로 격리됩니다.
- 선택 가능한 **창구 번호(1~30)**는 화면을 쉽게 알아보기 위한 **로컬 표시용 정보**입니다. 자동 배정·직원 신원 인증·실제 창구 번호 조회를 제공하지 않습니다. 실제 격리는 서버가 발급하는 무작위 접수 코드와 직원 토큰으로 결정됩니다.
- `보조 모니터에 민원인 화면 열기` 링크는 `target="_blank"` + `rel="noopener noreferrer"`로 열립니다. 직원 `sessionStorage`와 민원인 새 창의 저장소 공유(복제)를 방지하며, 직원 토큰을 URL에 넣지 않습니다.
- 듀얼 모니터를 **한 대의 직원 PC와 한 브라우저 프로필**로 사용하면 입력장치·브라우저 프로필·OS 로그인은 여전히 공유됩니다. **직원 PC를 방문객이 직접 조작할 수 있도록 무인 개방하면 안 됩니다.** 대외 키오스크는 별도 관리 기기·제한된 브라우저 계정 및 기관 보안 승인이 권장됩니다.
- 중앙 관리자가 여러 직원의 접수를 한 화면에서 보는 **전 창구 통합 관리자 권한**은 아직 없습니다. 이것은 직원별 세션과 직원의 요청 확인을 위한 기능입니다. 중앙 감독 기능은 신원 인증과 접근권한 설계 후 구현해야 합니다.

## 인증 구조

- 고정 \`APP_ACCESS_KEY\`는 **이 접수 기능에서 요구하지 않습니다**. 기존 ASAD의 다른 기능 보호 설정은 변경하지 않습니다.
- \`/secret\` 경로를 아는 사람은 **자신의 빈 세션을 만들 수 있습니다**. 경로 은닉은 직원 인증이 아닙니다.
- 서버가 새 창구마다 10자리 임의 코드와 **256비트 비밀 직원 토큰**을 생성합니다.
- 직원 토큰은 생성 응답과 해당 데스크톱 탭의 \`sessionStorage\`에만 저장하며 QR/민원인 URL에는 포함하지 않습니다.
- 서버가 올바른 직원 토큰을 확인해야 대기열 열람·직원 확인·세션 종료·다음 단계 안내 발송이 가능합니다.
- 다른 창구 코드를 알아도 직원 토큰이 없으면 그 창구의 내역을 볼 수 없습니다.
- 따라서 이 구조는 **세션 격리**이지 **직원 신원 인증**이 아닙니다. 공개 인터넷에서 실제 민원 정보에 쓰려면 기관 승인 및 직원 계정/네트워크 접근 통제가 필요합니다.

## 운영 조건

- 배포 환경의 \`UPSTASH_REDIS_REST_URL\` + \`UPSTASH_REDIS_REST_TOKEN\` 또는 기존 ASAD가 인식하는 \`KV_REST_API_URL\` + \`KV_REST_API_TOKEN\` 등 **공유 Redis REST 저장소가 필요**합니다.
- Redis가 없다면 **운영 빌드는 503으로 실패**하고 허위 실시간 연결을 표시하지 않습니다. 개발 모드만 메모리 저장소를 사용합니다.
- 별도 Vercel 프로젝트는 필요하지 않습니다. 기존 ASAD 서버와 Redis를 재사용합니다. 실제 과금/무료 한도는 서비스 플랜과 사용량에 따릅니다.
- 내려받은 독립형 `apps/visitor-intake/index.html`도 15개 언어를 제공하며, 오늘 예약 1~108번·다른 날짜 예약(유효한 날짜 8자리와 번호 필수)을 로컬 키패드에서 입력할 수 있습니다. 같은 PC의 두 창에서만 공유하며 서버·외부 기기에는 전송하지 않습니다.
- 키오스크·직원 기능 모두 **같은 ASAD origin**에서 실행. Github Pages의 정적 데모에서 ASAD API로 직접 전송하지 않습니다.
- 입력은 언어 코드, 업무 인덱스, 예약 자기신고, 예약번호(숫자 1~108), **다른 날짜 예약일(YYYY-MM-DD, 날짜 검증)**로 제한합니다. 예약일을 전송할 때는 유효한 예약번호와 `예약함` 응답이 함께 있어야 합니다. 일반적인 당일 예약 선택은 날짜를 추가로 저장하지 않습니다. `/api/intake/live` 역시 열거형 예약일 선택과 검증된 날짜·번호만 전송하며, 그 밖의 필드는 400으로 거절합니다. 이름·여권번호·체류 관련 자유입력·음성/녹음은 수집하지 않습니다. 정보는 세션과 함께 2시간 뒤 삭제됩니다.
- **20번 전화번호(연락처) 변경 신고**는 직원에게 업무 선택만 전달합니다. 변경 전·후 전화번호는 입력받거나 저장하지 않으며, 전송은 법정 신고 또는 시스템 정보 변경의 완료를 뜻하지 않습니다. 실제 처리 경로와 요건은 담당 직원이 확인해야 합니다.
- 서버는 2시간 TTL, 세션당 최대 60건으로 제한하고, 기본 요청 제한 및 중복 제출 방지를 적용합니다.
- 브라우저에서도 민원인 선택 내용은 localStorage나 sessionStorage에 보관하지 않습니다.
- 음성 인식은 **아직 구현되지 않았습니다**. 실시간 전달되는 것은 버튼 선택 결과입니다.

## 품질 확인

- `npm run lint && npm run typecheck && npm test && npm run build`
- `src/intake/store.test.ts`: 토큰 권한 분리, 세션 만료, 예약번호 1~108 경계값·윤년 및 잘못된 날짜 검증, 입력 제한, 중복 제출, 민원인 제출→직원 조회→직원 확인→발권 기록.
- `scripts/e2e-intake-notice.mjs`: 직원 체크박스 3개 선택 및 만 원 단위 금액 지정 → 민원인 화면의 다국어/한국어 목록 표시와 삭제를 Chromium·WebKit에서 검사.\n- `scripts/e2e-intake-compat.mjs`: Chromium·WebKit에서 109번 차단, 108번 정상 전달, 다른 날짜(잘못된 날짜 수정 포함) 키패드 입력과 직원 화면 반영.
- ASAD GitHub Actions CI에서 기존 기능 회귀 검사.
- `scripts/e2e-intake-dual-monitor.mjs`: Chromium·WebKit에서 직원 2명 대기열 격리, 새 민원인 창의 토큰 비노출, 창구 화면 레이블·직원 새로고침 후 복원 확인.
- 기관 승인 후 실제 iPad Safari와 데스크톱 간 QR 연결·새로고침·멀티 창구·Wi-Fi 전환·세션 만료 실기기 시험 필요.

## 창구 구별

- 직원 화면 상단의 창구 번호 배지와 미러 카드 테두리는 창구마다 정해진 색을 씁니다(6색 순환).
- 받은 요청 목록의 각 줄에는 그 요청이 들어온 창구 번호가 붙습니다. 번호는 서버가 창구 세션에서 찍으므로 민원인이 바꿀 수 없습니다.
