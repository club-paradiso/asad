# 제주출입국 방문 목적 사전접수 · ASAD 실시간 연결

> 시범 기능. 공식 출입국 시스템이 아니며, 기관 보안·운영 승인 전 실제 민원에 사용하지 마세요.

## 주소

- **iPad 민원인용**: ASAD 배포 주소의 \`/intake\`
- **직원 데스크톱**: 같은 ASAD 배포 주소의 \`/secret\`
- GitHub Pages의 \`apps/visitor-intake/\`는 **정적 데모**이며 실시간 전송을 수행하지 않습니다.

## 사용

1. 직원 컴퓨터에서 \`/secret\` 접속 → **실시간 접수 시작** 클릭.
2. 화면의 10자리 접수 코드 또는 QR을 이용해 iPad에서 같은 ASAD의 \`/intake?desk=코드\` 열기.
3. 민원인이 언어(12종) → 업무(19종) → HiKorea 예약 자기신고(3종) 선택 → **직원 화면으로 전송**.
4. 직원 화면은 약 1.8초 주기로 접수 내역을 갱신. 표시되는 ID는 **접수 요청의 순번**일 뿐 번호표가 아닙니다.
5. 직원이 예약 증빙, 관서, 일시, 업무 적합성을 확인하고 결과를 표시.
6. 담당자가 실제 번호표를 직접 발급한 후 **번호표 전달 완료 기록** 클릭. 시스템 자체는 번호표를 출력하지 않음.
7. 사용 종료 시 **접수 세션 종료·삭제**를 클릭. 미종료 세션은 2시간 후 만료.

## 인증 구조

- 고정 \`APP_ACCESS_KEY\`는 **이 접수 기능에서 요구하지 않습니다**. 기존 ASAD의 다른 기능 보호 설정은 변경하지 않습니다.
- \`/secret\` 경로를 아는 사람은 **자신의 빈 세션을 만들 수 있습니다**. 경로 은닉은 직원 인증이 아닙니다.
- 서버가 새 창구마다 10자리 임의 코드와 **256비트 비밀 직원 토큰**을 생성합니다.
- 직원 토큰은 생성 응답과 해당 데스크톱 탭의 \`sessionStorage\`에만 저장하며 QR/민원인 URL에는 포함하지 않습니다.
- 서버가 올바른 직원 토큰을 확인해야 대기열 열람·직원 확인·세션 종료가 가능합니다.
- 다른 창구 코드를 알아도 직원 토큰이 없으면 그 창구의 내역을 볼 수 없습니다.
- 따라서 이 구조는 **세션 격리**이지 **직원 신원 인증**이 아닙니다. 공개 인터넷에서 실제 민원 정보에 쓰려면 기관 승인 및 직원 계정/네트워크 접근 통제가 필요합니다.

## 운영 조건

- 배포 환경의 \`UPSTASH_REDIS_REST_URL\` + \`UPSTASH_REDIS_REST_TOKEN\` 또는 기존 ASAD가 인식하는 \`KV_REST_API_URL\` + \`KV_REST_API_TOKEN\` 등 **공유 Redis REST 저장소가 필요**합니다.
- Redis가 없다면 **운영 빌드는 503으로 실패**하고 허위 실시간 연결을 표시하지 않습니다. 개발 모드만 메모리 저장소를 사용합니다.
- 별도 Vercel 프로젝트는 필요하지 않습니다. 기존 ASAD 서버와 Redis를 재사용합니다. 실제 과금/무료 한도는 서비스 플랜과 사용량에 따릅니다.
- 키오스크·직원 기능 모두 **같은 ASAD origin**에서 실행. Github Pages의 정적 데모에서 ASAD API로 직접 전송하지 않습니다.
- 입력은 언어 코드, 업무 인덱스, 방문예약 자기신고 세 가지뿐입니다. 이름·여권번호·체류 관련 자유입력·음성/녹음은 수집하지 않습니다.
- 서버는 2시간 TTL, 세션당 최대 60건으로 제한하고, 기본 요청 제한 및 중복 제출 방지를 적용합니다.
- 브라우저에서도 민원인 선택 내용은 localStorage나 sessionStorage에 보관하지 않습니다.
- 음성 인식은 **아직 구현되지 않았습니다**. 실시간 전달되는 것은 버튼 선택 결과입니다.
