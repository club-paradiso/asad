# Translation quality benchmark

## What was measured, and what was not

ASAD has no provider credential in this environment and no authorisation to
spend, so **no model output was generated or scored**. What this benchmark
measures is the deterministic layer that stands between a model's output and
the person reading it: the integrity validator (`src/counter/integrity.ts`)
and the negation check (`src/counter/negation.ts`). Those are the components
that decide whether a visitor sees a warning on a correct translation, or no
warning on a corrupted one.

Human bilingual review and real-provider evaluation remain **NOT VERIFIED**;
the corpus and harness here are built so that both can be run later with the
same fixtures.

## Corpus

`benchmarks/counter/corpus.ts` — 44 synthetic cases, 67 faithful renderings,
62 deliberate corruptions. Written for this benchmark; no real applicant data.

Domains: extension, status change, registration card, address change,
workplace change, documents, appointment/HiKorea, fees, expiry, refugee
procedure, correction, clarification, mixed-language, unfinished sentences.

Pairs: ko→en (33 faithful), en→ko (8), ko→vi, vi→ko, ko→zh-CN, zh-CN→ko,
ko→zh-TW, ko→ja, ko→ru, ru→ko, ko→ar, ar→ko, ko→th, th→ko, ko→id, ko→mn,
ko→uz, ko→hi, hi→ko.

Corruption classes: status-code (7), negation (20), date (8), time (5),
number (9), money (5), invented value (5), identifier (3).

## Results

Same corpus, validators from `main` (2e57a0a) versus this branch:

| | Faithful flagged (false positives) | Corruptions missed (false negatives) |
| --- | --- | --- |
| `main` | **31 / 67 (46.3%)** | 1 / 62 (1.6%) |
| this branch | **0 / 67 (0.0%)** | **0 / 62 (0.0%)** |

The one corruption `main` missed — "about 3 weeks" rendered as "about 3 days"
— is now caught by the new `duration` value kind.

Per pair, per defect and the full finding list are regenerated by
`npm run bench:counter` into `benchmarks/results/counter-latest.md`.

### Honest caveat

The corpus and the fixes were developed together. A validator that passes a
corpus its author wrote is evidence that the named failure modes are gone,
not evidence of general accuracy. The regression gate in
`counter.bench.test.ts` keeps the corpus from drifting; the next step is a
corpus written by someone else, ideally from anonymised real desk exchanges.

## What changed in the validators

| Change | Why | Example that used to be flagged |
| --- | --- | --- |
| 12-hour times (`3 PM`, `3pm`, `3 p.m.`, `3 o'clock`), Korean 반, CJK 時/点/半, Vietnamese giờ/rưỡi, Hindi बजे | Only `HH:MM` and Korean N시 were read | 오후 3시 → "3 PM" |
| Bare hours marked ambiguous (`~03:00`) and matched by hour mod 12 | "3시" has no meridiem; "3 PM" is a faithful reading | 3시가 아니라 13시 → "not 3 PM, 13:00" |
| Currency words (won, dollars, yen, yuan, ウォン, вон, وون …) | Only symbols and Korean words were currency | 50,000원 → "50,000 won" |
| East Asian scales 만/천/백/억/万 | "6만" read as the integer 6 | 6만 원 → "60,000 won" |
| Thousands separators in amounts (`30.000 won`) | Read as 30.0 | 3만 원 → Indonesian "30.000 won" |
| Number words as *soft* matches (English 0–20 and tens, ordinals, months; Korean native numerals with counters; 1–10 in 20 languages; 二–十) | Spelled-out quantities read as lost digits | 서류 3장 → "three documents"; 두 번째 창구 → "counter 2" |
| Soft only — never raises an issue | "One moment, please" must not be an invented 1 | 잠시만요 → "One moment, please" |
| CJK dates 年/月/日 | Only Korean 년/월/일 | 2026년 9월 7일 → 2026年9月7日 |
| "15th of March" | Pattern missing | 3월 15일 → "the 15th of March" |
| Digits adjacent to non-Latin letters | Lookbehind rejected any letter, so 3番 and 下午3点 were invisible | 3번 창구 → 3番窓口 |
| Duration kind (15일 이내 / 15 days / 15 天 / 15 ngày) | Deadline units were not compared | 3주 → "3 days" now caught |
| Title-case administrative terms are not names | "Alien Registration Card" reported missing in Korean | Please bring your Alien Registration Card |
| Negation exclusions: Vietnamese sentence-final không/chưa, Chinese A-not-A and courtesy formulae, Japanese 無料/不便/ませんか, English "No. 2", Thai มิ, Korean 아닙 | Question particles and politeness are not negation; 아닙니다 was missed | Bạn có hẹn không?; 不好意思; 無料です |

Person-name verification was kept: a Latin name that vanishes into Korean
still produces a "please check" — the design intent in `integrity.test.ts`.

## Language coverage of the checks

| Check | Covered | Knowingly absent |
| --- | --- | --- |
| Negation | en, ko, zh, ja, vi, th, id, ru, es, fr, de, pt, ar, ur, hi, bn, tl, mn, tr | uz, ne, km, my, ug (suffix negation a token matcher cannot read honestly) |
| Number words | en, ko, zh, ja, vi, ru, uk, es, fr, de, pt, id, tr, uz, tl, mn, hi, ne, bn, ur, ar, th | km, my, ug |
| Durations | ko, en, zh, ja, vi (elsewhere the number alone is compared) | — |
| Times | Latin, Korean, CJK, Vietnamese, Hindi/Nepali | Thai, Khmer, Burmese word-forms |

Where a check is absent it returns no verdict rather than a guess — the
existing policy, kept.

## Quality dimensions this cannot assess

Semantic fidelity, omission, hallucinated clauses without values, modality,
register, naturalness, terminology consistency across turns. These need model
output and bilingual reviewers. The prompt's rules for them are unchanged.
